# Сервис выбора тем курсовых работ

Консольное приложение для автоматизации распределения тем курсовых проектов и управления подачей и согласованием заявок студентов на основе объектно-ориентированной модели (ООП).

## Назначение
Сервис предназначен для регламентации и автоматизации распределения тем курсовых работ между студентами и преподавателями кафедры. Система устраняет непрозрачность распределения тем, конфликты одновременного выбора темы несколькими соискателями, автоматизирует проверку академических критериев (курс, GPA) и учет квот доступных мест.

## Целевая аудитория
- **Студенты**: просмотр актуального каталога тем по академическим дисциплинам, проверка допуска, подача электронных заявок, мониторинг их статуса.
- **Преподаватели (научные руководители)**: формирование каталога тем с установлением квот мест и академических цензов, рецензирование и утверждение заявок.
- **Учебный отдел и сотрудники кафедры**: сводный мониторинг хода распределения тем, аналитическая статистика по успеваемости и статусам заявок.

## Предметная область
Организация процесса курсового проектирования в вузе. Сущности предметной области связаны между собой: заявка сопоставляет конкретного студента с выбранной темой курсовой работы и контролирует соблюдение академических требований и квот мест.

## Основные сущности и классы (ООП, ПР3)

### 1. `Topic` — Тема курсовой работы (модуль `models.topics`)
Представляет тему курсовой работы, доступную для выбора студентами.
- **Атрибуты**:
  - `id: int` — уникальный идентификатор темы;
  - `title: str` — наименование темы курсовой работы;
  - `discipline: str` — академическая дисциплина;
  - `supervisor: str` — научный руководитель;
  - `min_course: int` — минимальный допустимый курс обучения;
  - `min_gpa: float` — минимальный требуемый средний балл GPA;
  - `capacity: int` — квота мест (максимальное число студентов);
  - `current_students: int` — текущее количество записанных студентов;
  - `is_available: bool` — флаг доступности для выбора.
- **Методы**:
  - `is_suitable_for(student_course, gpa) -> bool` — проверка соответствия академическим требованиям;
  - `has_free_capacity() -> bool` — проверка наличия свободных мест;
  - `reserve_slot() -> bool` — бронирование/занятие места на тему;
  - `release_slot() -> None` — освобождение места при отмене заявки;
  - `@staticmethod validate_capacity(capacity) -> bool` — валидация корректности квоты;
  - `@classmethod from_dict(data) -> Topic` — фабричный метод создания объекта из JSON;
  - `to_dict() -> dict` — сериализация объекта в словарь для JSON;
  - `__str__() -> str` — строковое представление объекта темы.

### 2. `Student` — Студент (модуль `models.students`)
Представляет соискателя темы курсовой работы.
- **Атрибуты**:
  - `id: int` — идентификатор студента;
  - `name: str` — ФИО студента;
  - `course: int` — текущий курс обучения;
  - `gpa: float` — средний академический балл (GPA);
  - `is_budget: bool` — форма обучения (бюджетная / контрактная);
  - `email: str` — корпоративный адрес электронной почты.
- **Методы**:
  - `calculate_priority() -> int` — расчет приоритета заявки на основе GPA и формы обучения;
  - `@classmethod from_dict(data) -> Student` — создание объекта из словаря JSON;
  - `to_dict() -> dict` — сериализация объекта в словарь для JSON;
  - `__str__() -> str` — строковое представление студента.

### 3. `Application` — Заявка (модуль `models.applications`)
Осуществляет композицию и связывание объектов `Topic` и `Student`.
- **Атрибуты**:
  - `id: int` — номер заявки;
  - `topic: Topic` — прямая ссылка на объект темы курсовой работы;
  - `student: Student` — прямая ссылка на объект студента-заявителя;
  - `application_date: str` — дата подачи заявки;
  - `priority: int` — численный рейтинг/приоритет заявки;
  - `is_cancelled: bool` — флаг отмены заявки.
- **Методы и свойства**:
  - `cancel() -> None` — отмена заявки с вызовом `topic.release_slot()`;
  - `@property status -> str` — динамическое свойство возврата строкового статуса («ОДОБРЕНА» / «ОТМЕНЕНА»);
  - `to_dict() -> dict` — сохранение внешних ключей `topic_id` и `student_id` для JSON;
  - `__str__() -> str` — наглядное строковое представление карточки заявки.

## Взаимодействие объектов
```text
  ┌───────────────┐               ┌─────────────────┐
  │    Student    │               │      Topic      │
  │───────────────│               │─────────────────│
  │ id: int       │               │ id: int         │
  │ name: str     │               │ title: str      │
  │ course: int   │               │ min_course: int │
  │ gpa: float    │               │ min_gpa: float  │
  └───────┬───────┘               └────────┬────────┘
          │ 1                              │ 1
          │          ┌─────────────┐       │
          └─────────►│ Application │◄──────┘
                     │─────────────│
                     │ id: int     │
                     │ priority    │
                     │ is_cancelled│
                     └─────────────┘
```
При создании заявки функция `create_application()` валидирует студента через метод `topic.is_suitable_for()`, затем вызывает `topic.reserve_slot()`, резервируя место. При вызове `app.cancel()` заявка помечается отмененной, а метод `topic.release_slot()` освобождает место по квоте темы.

## Требования
- Python 3.10+
- pytest >= 8.0
- flake8 >= 7.0

Установка зависимостей:
```bash
pip install -r requirements.txt
```

## Запуск веб-приложения на базе Django (ПР5, ПР6)

### 1. Подготовка базы данных и загрузка начальных данных:
```bash
python manage.py migrate
python manage.py seed_data
```

### 2. Запуск локального сервера разработки:
```bash
python manage.py runserver
```
Веб-интерфейс доступен по адресу: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### 3. Основные страницы веб-приложения:
- **Каталог тем**: `http://127.0.0.1:8000/` (с поиском и фильтром по дисциплинам)
- **Реестр студентов**: `http://127.0.0.1:8000/students/`
- **Журнал заявок**: `http://127.0.0.1:8000/applications/`
- **Подача заявки**: `http://127.0.0.1:8000/apply/` (с динамической валидацией требований)
- **Панель аналитики**: `http://127.0.0.1:8000/statistics/`
- **Панель администратора**: `http://127.0.0.1:8000/admin/`

### 4. Документированные эндпоинты RESTful JSON API:
- `GET /api/topics/` — каталог тем курсовых работ
- `GET /api/topics/<id>/` — карточка конкретной темы
- `POST /api/applications/create/` — подача заявки в формате JSON (`{"student_id": 1, "topic_id": 1}`)
- `GET /api/statistics/` — аналитическая статистика
- `GET /api/health/` — эндпоинт мониторинга работоспособности сервера (health-check)

```bash
curl http://localhost/api/health/
```
