# Сервис выбора тем курсовых работ

Веб-приложение на базе Django для автоматизации распределения тем курсовых проектов и управления подачей и согласованием заявок студентов между преподавателями и соискателями кафедры индустриального программирования РТУ МИРЭА.

## 1. Назначение и предметная область
Сервис предназначен для регламентации и автоматизации распределения тем курсовых работ между студентами и преподавателями кафедры. Система исключает непрозрачность выбора тем, устраняет коллизии одновременного закрепления темы несколькими студентами, автоматизирует проверку академических критериев (курс, GPA) и контроль квот мест.

### Сущности системы:
1. **Discipline (Дисциплина)** — академический предмет кафедры.
2. **Student (Студент)** — соискатель темы (курс, средний балл GPA, бюджет/договор, вычисленный статус отличника `is_honor_student`).
3. **Topic (Тема курсовой работы)** — тема исследования со связью с дисциплиной, научным руководителем, пороговыми требованиями допуска, квотой мест, каноническим слагом (`slug`), иллюстрацией (`image`) и вычисленным статусом командной темы `is_competitive`.
4. **Application (Заявка на тему)** — документ закрепления студента за темой со статусами (`active`, `cancelled`, `completed`), датой подачи, приоритетом и связями `ForeignKey` с `on_delete=models.PROTECT`.

## 2. Архитектура и этапы развития (ПР9, ПР10, ПР11)

### ПР9: Модели Django, связи и операции с базой данных через ORM
- Реализованы реляционные модели `Discipline`, `Student`, `Topic`, `Application` с внешними ключами `ForeignKey(on_delete=models.PROTECT, related_name=...)`.
- Выполнены миграции структуры базы данных SQLite (`topics/migrations/`).
- Реализованы скрипты инспекции структуры (`db/inspect_source_db.py`) и транзакционной верификации данных (`db/import_sqlite_to_orm.py`).
- Реализованы и протестированы 16 типовых выражений Django ORM (`topics/management/commands/demonstrate_orm_queries.py`):
  `all()`, `filter()`, `exclude()`, `order_by()`, `get()`, `values()`, `values_list()`, `select_related()`, `Q()`, `aggregate(Avg, Max, Min)`, `annotate(Count)`, `exists()`, `count()`, `Paginator`, кастомные QuerySet методы и `GeneratedField`.

### ПР10: Административная панель Django и работа с данными через ORM
- Развернута и кастомизирована административная панель Django (`topics/admin.py`):
  - Кастомизация заголовков интерфейса РТУ МИРЭА (`site_header`, `site_title`, `index_title`).
  - Регистрация `ModelAdmin` для всех моделей со свойствами: `list_display`, `list_display_links`, `list_filter`, `search_fields`, `ordering`, `list_per_page=20`.
  - Безопасное инлайн-редактирование `list_editable = ("capacity",)`.
  - Табличные вложенные формы `ApplicationTabularInline` внутри карточек тем и студентов.
  - Поиск с автодополнением `autocomplete_fields = ("student", "topic", "discipline")`.
  - Иерархическая навигация по датам `date_hierarchy = "application_date"`.
  - Оптимизация обращений к связанным таблицам `list_select_related` для полного исключения проблемы N+1 запросов.
  - Пользовательские групповые действия (Admin Actions): `cancel_applications` и `restore_applications`.
  - Прямой переход из карточки темы в пользовательский веб-интерфейс (`view_on_site = True`, метод `get_absolute_url()`).
- Переход от булева флага к перечислению `Application.Status(models.TextChoices)` (`ACTIVE`, `CANCELLED`, `COMPLETED`).
- Кастомный менеджер и `ApplicationQuerySet` с методами `.active()`, `.cancelled()`, `.completed()`, `.for_date()`.
- Использование `GeneratedField` (Django 5.0+) с `db_persist=True` для вычисляемых на уровне СУБД полей (`is_honor_student` и `is_competitive`).
- Автоматическая транслитерация и генерация уникальных URL-слагов (`SlugField`) тем с использованием библиотеки `unidecode` и `slugify`.
- Кастомный контекстный процессор `topics.context_processors.topic_context`, поставляющий глобальные переменные (`site_name`, `topics_total_count`, `active_topics_count`) во все шаблоны.
- Интеграция `django-debug-toolbar` для профилирования и анализа SQL-запросов.

### ПР11: Формы в Django
- **TopicFilterForm (`forms.Form`)**: форма поиска и фильтрации каталога тем с передачей параметров через безопасные GET-запросы, сохранением состояния формы и сортировкой.
- **ApplicationForm (`forms.ModelForm`)**: форма создания заявки с виджетами Bootstrap и кросс-полевой валидацией в методе `clean()`:
  - проверка запрета повторной подачи заявки на ту же тему;
  - проверка соответствия курса и среднего балла (GPA) студента минимальным требованиям темы;
  - проверка наличия свободных мест по квоте темы.
- **ApplicationEditForm (`forms.ModelForm`)**: редактирование существующей заявки с использованием параметра `instance` и метода `exclude(pk=self.instance.pk)` при валидации конфликтов.
- **TopicForm (`forms.ModelForm`)**: создание и редактирование темы с валидацией диапазонов квот и GPA, а также поддержкой загрузки файлов изображений (`ImageField`, `request.FILES`, `enctype="multipart/form-data"`, библиотека Pillow).
- Защита всех модифицирующих запросов токенами CSRF (`{% csrf_token %}`) и декоратором `@require_POST`.
- Постраничная навигация списка тем и журнала заявок с помощью класса `Paginator`.

## 4. Установка и запуск

### 1. Установка зависимостей:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Применение миграций и загрузка данных:
```bash
python manage.py migrate
python manage.py seed_data
```

### 3. Запуск сервера разработки:
```bash
python manage.py runserver
```
Сервис доступен по адресу: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### 4. Доступ к административной панели:
Адрес: [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/)  
Учетная запись суперпользователя: `admin` / `admin123`
